# 13.0 — Objetivos y contexto

> **Capítulo 13: Contratos formales para software moderno.** Competencias globales del capítulo:
> - Definir contratos modernos con el cálculo de predicados.
> - Separar propiedades internas de hipótesis externas.

## Competencias de esta sección

- **Conocimiento:** definir con precisión los términos y expresiones de «objetivos y contexto».
- **Desempeño:** aplicar el cálculo de predicados y las transformaciones justificadas en un problema concreto.
- **Evidencia:** entregar una especificación o derivación anotada, con hipótesis explícitas y límites de validez.

> **Material complementario original:** aplicación actual de los métodos de Kaldewaij; no corresponde a una sección del libro de 1990.

## Desarrollo

En un programa de arreglos la «operación primitiva» es una asignación con semántica definida; en una API aparecen operaciones externas que pueden terminar con éxito, error o no respuesta. Para aplicar formalmente el método, se debe **definir el modelo de la operación externa** en lugar de fingir que `predict(x)` siempre retorna.

Una API se puede describir como transición de un estado de solicitud `req` a una respuesta `resp` y, si corresponde, cambios de estado persistente. El contrato es:

$$\{P(req,env)\}\ endpoint(req)\ \{Q(req,resp,env')\}.$$

`env` representa las partes observables del entorno de ejecución, según el alcance escogido. Si no se modelan cierres abruptos, fallas de host ni concurrencia, **no afirmar** que la prueba cubre dichos fenómenos.

## Comprobación de competencia

1. Formula la propiedad central como un predicado explícito, indicando el dominio y las condiciones de definibilidad.
2. Justifica una transformación algebraica relevante sin usar solo ejemplos concretos como prueba.
3. Construye un caso límite que pueda refutar una hipótesis insuficiente.
4. Declara qué parte está demostrada y cuál constituye solamente evidencia experimental.
