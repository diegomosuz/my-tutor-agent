# 18.1 — Especificación formal del endpoint

## Competencias de esta sección

- **Conocimiento:** definir con precisión los términos y expresiones de «especificación formal del endpoint».
- **Desempeño:** aplicar el cálculo de predicados y las transformaciones justificadas en un problema concreto.
- **Evidencia:** entregar una especificación o derivación anotada, con hipótesis explícitas y límites de validez.

> **Material complementario original:** aplicación actual de los métodos de Kaldewaij; no corresponde a una sección del libro de 1990.

## Desarrollo

Sea `x=(a,i,t)`; `result` el resultado externo discriminado y `resp` la respuesta pública:

$$V(x)\equiv0\le a\le120\land0\le i\le10^6\land finite(i)\land0\le t\le600,$$

con `a,t` enteros e `i` real. Sea:

$$R(p,v)\equiv 0\le p\le1\land finite(p)\land isinstance(v,string)\land |trim(v)|>0.$$

Contrato observable:

$$\begin{aligned}
Q\equiv{}& (Success(p,v)\Rightarrow V(x)\land Returned(p,v)\land R(p,v))\\
&\land (InvalidInput\Rightarrow\neg V(x))\\
&\land (InferenceError\Rightarrow V(x)\land externalFailure)\\
&\land (\neg V(x)\Rightarrow calls=0)\\
&\land (V(x)\Rightarrow calls\le1).
\end{aligned}$$

`externalFailure` incluye timeout, error HTTP, JSON inválido o resultado que no cumple `R`. `calls` cuenta intentos explícitos de aplicación realizados por esta API, no paquetes TCP ni operaciones internas de bibliotecas. Se presupone que el validador clasifica los JSON de acuerdo con `V`.

## Comprobación de competencia

1. Formula la propiedad central como un predicado explícito, indicando el dominio y las condiciones de definibilidad.
2. Justifica una transformación algebraica relevante sin usar solo ejemplos concretos como prueba.
3. Construye un caso límite que pueda refutar una hipótesis insuficiente.
4. Declara qué parte está demostrada y cuál constituye solamente evidencia experimental.
